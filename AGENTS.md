# Aspose CLI repository guide

This directory is a complete independent open-source CLI project. Its executable is `aspose-cli`.
The only active product roster is `eng/products.json`; fixed distribution identity is in `eng/distribution.json`.
Generated projections and the solution are regenerated by `scripts/sync.ps1`, never hand-edited.
All source, project references, build imports, tests and publishing tools must remain inside this project.
Do not reference its parent workspace or sibling CLI project. Host, SDK and analyzer code are owned here.

## Architecture and safety

- Launcher -> Host -> SDK; launcher -> active Products; Products -> SDK. Products never reference another Product.
- SDK types from a document engine remain inside its matching Product Engine adapter.
- Keep files primary; never round-trip an entire document through JSON.
- Preserve atomic publication, bounded extraction, resource budgets, worker cancellation and rollback.
- Preserve loopback HTTP, exact Host, same-origin, CSRF and current-user service control.
- Product ids come from the catalog; distribution metadata identifies this executable.
- Preserve user files and unrelated worktree changes. Never clean unknown files.
- Tests use real engines and real CLI processes, not engine mocks.
- Code comments, diagnostics, documentation and Skills are English.
- Do not add old-command aliases, legacy installer/Skill readers or historical version baselines.
- The application is pre-release. Update code, schemas, Skills and tests together for intentional contract changes.
- File publication and per-user install/PATH transactions use resource-based interprocess locks even across the two CLI products.

## Product ownership

Each Product owns Contracts, Ports, Engine, Commands, Output, Schemas/v2, Preview, Skills and its module definition.
Definitions are pure and deterministic. Do not introduce product-specific Host branches.
Skill names begin with `aspose-cli-` and executable examples must match this build's capabilities.
Package-relative documentation links must resolve. Existing files must be safely preserved on mutation.

## Commercial engines

Use only corresponding commercial Aspose SDK packages. No FOSS source or gitlinks are required.
Preserve licensed and evaluation behavior and honestly disclose evaluation output changes.
The CLI source license does not replace the SDKs' own license terms.

## Verification

Run `scripts/sync.ps1`, `scripts/test.ps1 -Configuration Release`, and `scripts/publish.ps1 -Configuration Release`.
Also verify a win-x64 self-contained publish and install/update isolation.
This project must pass from a standalone checkout without the parent workspace or sibling project.
